## Назначение

При первом запуске host-harvester проходит по местам и путям, указанным в профиле. При необходимости он монтирует указанный раздел, извлекает перечисленные файлы и значения и сохраняет результаты в постоянное хранилище. Потребители получают сохранённые результаты через интерфейс host-harvester. Данные доступны после перезагрузки и размонтирования исходного раздела.

Потребители запрашивают сохранённые данные по ключу. Файлы, включая двоичные, доступны по пути или через открытый дескриптор для чтения. Дескриптор переходит во владение потребителя. Текстовые значения возвращаются строкой. Например, профиль платы может извлечь заводские адреса Wi-Fi и Bluetooth из раздела persist для использования другими компонентами.

## Сокет потребителей и ранняя загрузка

Потребители подключаются к `/run/host-harvester/socket` и запрашивают данные по ключу. Файлы доступны по пути или через дескриптор для чтения, переданный через Unix-сокет. Текстовые значения возвращаются строкой. Сокет создаётся при загрузке. Собранные данные лежат в постоянном хранилище.

Для ранней загрузки `nobscur-init` должен открыть доступ к хранилищу и запустить сервис чтения до потребителей. При первой загрузке нужно извлечь и сохранить прошивку тача до загрузки `nt36532`. Модуль сейчас использует Linux `request_firmware`, поэтому помощник в initramfs должен получить прошивку через сокет и сделать её доступной под настроенным именем в `/lib/firmware` до загрузки модуля. Потребитель в userspace может получить дескриптор напрямую. После смены корня обычный сервис чтения использует тот же путь сокета.

## Запуск

В профиле перечисляются каталоги или блочные устройства. У каждой записи есть уникальный ключ, относительный путь и тип `file` или `text`. Для доступного каталога пропустите `filesystem`. Для блочного устройства укажите тип файловой системы, чтобы ранняя загрузка могла смонтировать его напрямую через Linux. [Пример профиля TB371FC](profiles/example.toml) использует пути запущенной системы. В initramfs укажите каталог прошивок под смонтированным корнем, например `/sysroot/usr/lib/firmware`, и убедитесь, что путь к блочному устройству доступен. В примере ниже внешняя прошивка уже подготовлена в исходном каталоге.

```toml
[[sources]]
path = "/sysroot/opt/board-inputs"

[[sources.entries]]
key = "touch.firmware"
path = "novatek/novatek_ts_tm_fw_6.bin"
kind = "file"
```

До загрузки `nt36532` смонтируйте настоящий корень и откройте хранилище на запись. Запустите `serve` отдельным процессом и дождитесь строки `ready` перед командой подготовки прошивки.

```sh
host-harvester collect /etc/host-harvester.toml /sysroot/var/lib/host-harvester /run/host-harvester/work
host-harvester serve /sysroot/var/lib/host-harvester /run/host-harvester/socket
host-harvester prepare-firmware /run/host-harvester/socket touch.firmware /lib/firmware/novatek/novatek_ts_tm_fw_6.bin
```

Импорт становится доступен после сохранения всех записей. Неудачный импорт можно повторить. После успешного импорта `collect` пропускает исходные разделы при следующих запусках. Остановите ранний сервис перед сменой корня. В обычной системе запустите `serve /var/lib/host-harvester /run/host-harvester/socket`. Новые каталог сокета и хранилище по умолчанию доступны владельцу. Потребителям, использующим пути, также нужны права на чтение файлов хранилища. Rust-клиенты могут использовать `SocketReader` и интерфейс `StorageReader`.

В Linux `hharvester-mount::MountedDisk` монтирует указанный раздел внутри существующей рабочей директории. Метод `read_file` принимает относительный путь. Вызов `unmount` позволяет обработать ошибку размонтирования. При уничтожении объекта крейт также пытается размонтировать раздел. Для монтирования нужны соответствующие права. Вариант `mount_with_filesystem` обращается к ядру напрямую. Вариант `mount` использует команды `mount` и `umount` для автоматического определения файловой системы.
